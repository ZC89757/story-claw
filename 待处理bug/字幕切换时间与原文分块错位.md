# 字幕切换时间与原文分块错位

## 状态
待处理

## 现象
部分字幕在对应文字尚未朗读完时提前消失，下一条字幕提前出现。

## 主要根因
`runner/render.ts` 中字幕文字按字符数和标点切块，但 TTS 返回的 `timedWords` 按“字幕块数量”平均分配：

```ts
startWord = Math.floor(ci * timedWords.length / chunks.length);
endWordExclusive = Math.floor((ci + 1) * timedWords.length / chunks.length);
```

该算法假设每个字幕块对应相同数量的 TTS words。实际字幕块长度通常不相等，英文、数字和版本号经过 TTS 文本标准化后，word 数量也不等同于原文字符数，因此字幕块会映射到错误的时间边界。

## 已确认案例
项目：`workspace/20260801/ep01`

### `render_04/g04`
三个字幕块长度约为：

```text
55 / 25 / 25
```

第一块占原文约 52%，代码却只分配前 1/3 的 TTS words，导致第一条字幕提前结束、第二条提前出现。

### `render_04/g01`
四个字幕块长度约为：

```text
28 / 25 / 22 / 10
```

第四块按原文位置应在约 88% 处开始，代码却在 75% 的 TTS words 位置开始显示。

## 次要影响
最终全局合并可能统一调整音频速度，而字幕已经烧录在原速视频中。例如本集音频使用 `atempo=0.9886` 放慢约 1.15%，字幕时间不会同步拉长，会进一步产生轻微提前。

## 建议修复方向
1. 保留 `synthSegs[j].text` 作为字幕显示文字。
2. 保留豆包 TTS 返回的 `startTime/endTime` 作为时间来源。
3. 不再按字幕块数量平均瓜分 `timedWords`。
4. 根据每个字幕块在完整原文中的累计字符位置，将边界对齐到 TTS words 拼接文本中的实际位置。
5. 对 `V4`、`GPT-5.6`、百分比、日期等标准化差异建立原文到 TTS 文本的归一化对齐。
6. 后续评估字幕烧录后、音频全局调速造成的时间漂移，必要时让字幕时间同步缩放或改为逐 group 对齐。

- `runner/render.ts`：ASS 生成与 group 视频字幕烧录
- `runner/render.ts`：最终音视频全局对齐
